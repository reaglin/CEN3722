Identifying Heuristic Violations in a Login Screen

  • **Problem:** A user testing session reveals the following issues with a banking app's login screen: (1) After a failed login attempt, the screen simply clears and resets with no message. (2) The "Submit" button is grayed out with no explanation of why it is disabled. (3) Error recovery requires calling customer support. Identify which of Nielsen's 10 Usability Heuristics are violated in each case, name the heuristic, and briefly explain its meaning.
  • **Step 1 — Recall all 10 heuristics.** Nielsen's 10 Usability Heuristics are: (1) Visibility of System Status, (2) Match Between System and the Real World, (3) User Control and Freedom, (4) Consistency and Standards, (5) Error Prevention, (6) Recognition Rather Than Recall, (7) Flexibility and Efficiency of Use, (8) Aesthetic and Minimalist Design, (9) Help Users Recognize, Diagnose, and Recover from Errors, and (10) Help and Documentation.
  • **Step 2 — Analyze Issue 1 (screen clears, no message).** The system gives the user no feedback about what happened or why. This violates **Heuristic 1: Visibility of System Status**. This heuristic states the system should always keep users informed about what is going on through appropriate feedback within a reasonable time.
  • **Step 3 — Analyze Issue 2 (grayed-out button, no explanation).** The user cannot tell why the button is disabled, requiring them to mentally recall what might be missing. This violates **Heuristic 6: Recognition Rather Than Recall**. This heuristic states the interface should minimize the user's memory load by making options, actions, and information visible, so users do not have to remember information from one part of the interface to another.
  • **Step 4 — Analyze Issue 3 (must call support to recover).** The system provides no in-app pathway to diagnose or fix the problem. This violates **Heuristic 9: Help Users Recognize, Diagnose, and Recover from Errors**. This heuristic states error messages should be expressed in plain language, precisely indicate the problem, and constructively suggest a solution — all within the interface itself.
  • **Summary Answer:** Issue 1 → Heuristic 1 (Visibility of System Status). Issue 2 → Heuristic 6 (Recognition Rather Than Recall). Issue 3 → Heuristic 9 (Help Users Recognize, Diagnose, and Recover from Errors).

Matching Heuristics to Real-World Interface Examples

  • **Problem:** For each interface feature below, name the Nielsen heuristic it best exemplifies and explain what that heuristic means in your own words. (a) A word processor asks "Are you sure you want to delete this file? [Cancel] [Delete]" before permanently removing a file. (b) An e-commerce site uses a shopping cart icon instead of the label "Temporary Purchase Repository." (c) A photo editing app allows both a menu path and a keyboard shortcut (Ctrl+Z) to undo an action.
  • **Step 1 — Recall the 10 heuristics and their definitions (the foundation for all analysis).** Review the full list mentally or written out: Visibility of System Status; Match Between System and the Real World; User Control and Freedom; Consistency and Standards; Error Prevention; Recognition Rather Than Recall; Flexibility and Efficiency of Use; Aesthetic and Minimalist Design; Help Users Recognize, Diagnose, and Recover from Errors; Help and Documentation.
  • **Step 2 — Analyze feature (a): confirmation dialog before deletion.** Asking the user to confirm before an irreversible action directly prevents a mistake from happening in the first place. This exemplifies **Heuristic 5: Error Prevention**. Definition: It is better to design interfaces that prevent problems from occurring than to provide good error messages after the fact.
  • **Step 3 — Analyze feature (b): shopping cart icon using familiar terminology.** A "shopping cart" is an object from the physical retail world that users already understand. Using it avoids forcing users to learn system-specific jargon. This exemplifies **Heuristic 2: Match Between System and the Real World**. Definition: The system should speak the users' language, using words, phrases, and concepts familiar to the user rather than system-oriented terms, following real-world conventions so information appears in a natural and logical order.
  • **Step 4 — Analyze feature (c): both menu path and keyboard shortcut for undo.** Providing two methods for the same action serves both novice users (menu) and expert users (shortcut), accommodating a range of skill levels. This exemplifies **Heuristic 7: Flexibility and Efficiency of Use**. Definition: Accelerators — unseen by novice users — may speed up interaction for experts, allowing the interface to cater to both inexperienced and experienced users.
  • **Summary Answer:** (a) Heuristic 5 — Error Prevention. (b) Heuristic 2 — Match Between System and the Real World. (c) Heuristic 7 — Flexibility and Efficiency of Use.

This reduces 10 isolated items to 3 meaningful groups.
  • **Step 2 — Cluster A: Feedback & Information (Heuristics 1, 6, 8).** Heuristic 1 — **Visibility of System Status**: The system should always keep users informed about what is going on through timely, appropriate feedback. Heuristic 6 — **Recognition Rather Than Recall**: Minimize the user's memory load by making objects, actions, and options visible so users recognize rather than remember. Heuristic 8 — **Aesthetic and Minimalist Design**: Dialogues should not contain irrelevant or rarely needed information; every extra unit of information competes with relevant information and diminishes its visibility.
  • **Step 3 — Cluster B: Design Language & Control (Heuristics 2, 3, 4, 7).** Heuristic 2 — **Match Between System and the Real World**: Use familiar language and real-world conventions rather than system-oriented jargon. Heuristic 3 — **User Control and Freedom**: Users often choose functions by mistake and need clearly marked "emergency exits" to leave unwanted states without extended dialogue. Heuristic 4 — **Consistency and Standards**: Users should not have to wonder whether different words, situations, or actions mean the same thing; follow platform conventions. Heuristic 7 — **Flexibility and Efficiency of Use**: Allow accelerators so that expert users can complete frequent tasks faster, while the interface remains accessible to novices.
  • **Step 4 — Cluster C: Error & Support (Heuristics 5, 9, 10).** Heuristic 5 — **Error Prevention**: Carefully design the interface to prevent problems from occurring in the first place, which is better than any error message. Heuristic 9 — **Help Users Recognize, Diagnose, and Recover from Errors**: Error messages should be in plain language, indicate the problem precisely, and suggest a constructive solution. Heuristic 10 — **Help and Documentation**: Even though it is better if the system can be used without documentation, it may be necessary to provide help that is easy to search and focused on the user's task.

Applying Heuristic 3 — User Control and Freedom

  • **Problem:** A mobile email app does not have an "Undo Send" feature. Once the send button is tapped, the email is immediately and permanently delivered. A designer argues this is fine because "users should be careful before sending." Using Nielsen's Heuristic 3, explain why the designer's reasoning conflicts with usability principles, name the heuristic, explain its meaning, and describe what a heuristic-compliant solution would look like.
  • **Step 1 — Identify and define the relevant heuristic.** The scenario involves a user being unable to exit or reverse an action they regret. This directly relates to **Heuristic 3: User Control and Freedom**. Definition: Users often select functions by mistake and need a clearly marked "emergency exit" to leave an unwanted state without having to go through an extended dialogue. The heuristic supports undo and redo functionality.
  • **Step 2 — Evaluate the designer's reasoning against the heuristic.** The designer assumes users will not make mistakes and places full responsibility on the user for perfect performance. Heuristic 3, however, is grounded in the reality that errors are a normal, expected part of human behavior. Good interface design accommodates mistakes rather than assuming they will not occur. The designer's reasoning conflicts with this principle because it removes the user's ability to correct an accidental or regretted action.
  • **Step 3 — Describe a heuristic-compliant solution.** A compliant design would provide a brief time window (e.g., 5–10 seconds) after tapping "Send" during which a clearly visible "Undo" option appears at the bottom of the screen. If the user taps "Undo," the send is cancelled and the email returns to the drafts folder. If the window expires with no action, the email is sent. This gives users a clear emergency exit without requiring an extended process.
  • **Step 4 — Connect back to the broader principle.** This solution respects user autonomy, acknowledges human fallibility, and supports user confidence — users are more willing to explore and act decisively when they know mistakes are reversible. This is precisely what Heuristic 3 is designed to enable.
  • **Summary Answer:** Heuristic 3 (User Control and Freedom) is violated because users have no way to reverse an accidental send. The heuristic states users need "emergency exits" to leave unwanted states. A compliant solution is a timed "Undo Send" option that appears immediately after sending and cancels delivery if tapped within a short window.

Distinguishing Heuristic 4 (Consistency) from Heuristic 2 (Real-World Match)

  • **Problem:** Two usability issues are found in a project management web app: (a) On the "Tasks" page, completed tasks are marked with a green checkmark; on the "Reports" page, completed tasks are shown with a red X. (b) The app uses the internal developer term "Node Artifact" instead of the user-familiar term "File Attachment." Students often confuse Heuristics 2 and 4. Explain the difference between these two heuristics, then apply the correct one to each issue.
  • **Step 1 — Define Heuristic 2: Match Between System and the Real World.** This heuristic is about the language and concepts the system uses relative to the outside world and the user's prior knowledge. The system should use words, phrases, and metaphors that users already know from everyday life or their professional domain, rather than internal technical or system-specific language.
  • **Step 2 — Define Heuristic 4: Consistency and Standards.** This heuristic is about internal coherence within the system and conformity to platform conventions. Within the same product, the same action, symbol, or concept should always be represented the same way. Users should not have to wonder whether two different visual representations mean the same thing or something different.
  • **Step 3 — Key distinction between the two.** Heuristic 2 is an external comparison (system language vs. the real world). Heuristic 4 is an internal comparison (one part of the system vs. another part of the same system, or vs. established platform norms). If the problem is "the app uses unfamiliar jargon," that is Heuristic 2. If the problem is "the app uses two different symbols for the same thing in different places," that is Heuristic 4.
  • **Step 4 — Apply to Issue (a): green checkmark vs. red X for completed tasks.** Both symbols appear within the same application and represent the same status (task completed), yet they are visually opposite in meaning (green = positive/go; red = stop/negative). A user moving between pages must wonder what each symbol means. This is an internal inconsistency — a violation of **Heuristic 4: Consistency and Standards**.
  • **Step 5 — Apply to Issue (b): "Node Artifact" instead of "File Attachment."** "Node Artifact" is developer-internal jargon with no equivalent in the user's everyday world. "File Attachment" is the term users know from email and other common tools. The problem is a mismatch between system language and real-world language — a violation of **Heuristic 2: Match Between System and the Real World**.
  • **Summary Answer:** Heuristic 2 = system language vs. the real world (external). Heuristic 4 = consistency within the system (internal). Issue (a) violates Heuristic 4; Issue (b) violates Heuristic 2.
