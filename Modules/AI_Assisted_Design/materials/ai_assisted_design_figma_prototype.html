1. Purpose (Why This Matters)

In Phase 3 you produced a structured, AI-ready task analysis and an initial software flow. This phase turns that analysis into something a user can actually see and click: an interactive prototype built in Figma. This is where the use cases and tasks your team has been documenting all semester become a concrete, navigable design.

This mirrors how real product teams work. AI coding assistants can scaffold screens and flows quickly, but a designer's job is to assemble those pieces into a coherent prototype that covers every action a user needs to take. Building the full prototype now — before any polish or formal quality review — forces your team to confront whether your earlier analysis was actually complete. Gaps in the prototype usually reveal gaps in the task analysis, which is exactly what this phase is designed to surface while it is still cheap to fix.

The aim of this phase is breadth of coverage, not visual perfection. You are demonstrating that your design accounts for the full set of documented use cases and actions. Design quality itself will be evaluated in a later phase — here, the goal is simply to produce and submit a complete working prototype.

2. Learning Outcomes

By completing this assignment, your team will be able to:

  1. Construct an interactive Figma prototype whose screens and transitions cover all use cases and actions documented in your previous phases.
  2. Apply AI-accelerated prototyping workflows to generate and assemble low- to mid-fidelity screens efficiently.
  3. Synthesize your prior task analysis and software flow into a connected, navigable prototype rather than a set of disconnected screens.

3. The Task (Step-by-Step Instructions)

Key terms defined for this assignment:
  • Prototype — a set of connected Figma screens (frames) with working navigation, so a reviewer can click through and move from one screen to the next as a real user would.
  • Screen / frame — a single view of your application (one Figma frame).
  • Flow connection — a Figma prototype link that moves the user from one frame to another when an element is clicked.
  • Cover — for every documented use case and action, there is a screen (or sequence of screens) in the prototype that lets the user complete it.
  • Public link — a Figma share link whose access is set so that anyone with the link can view, with no login or invitation required.

Step 1 — Inventory what the prototype must cover (≈20 min)

As a team, list every use case and user action from your previous assignments. This list is your coverage checklist — each item must be reachable in the finished prototype. Carry your Phase 3 software flow alongside it as your map.

Step 2 — Generate and assemble screens (≈90 min)

Build a frame in Figma for each screen in your flow. You may use AI coding assistants or AI design tools to scaffold layouts quickly, then bring the results into Figma and arrange them. Aim for low- to mid-fidelity: the structure, content, and controls should be present and clearly labeled, but pixel-level polish is not required this phase.

Step 3 — Connect the flow (≈30 min)

Use Figma's prototyping links to connect your frames so a reviewer can click through each use case from start to finish. Every item on your Step 1 checklist should be navigable.

Step 4 — Verify coverage (≈20 min)

Walk through your own prototype against the Step 1 checklist. Confirm that each use case and action can be reached and completed. Note any gaps; if a gap reveals a missing screen, add it.

Step 5 — Capture screens and publish the link (≈20 min)

Take a screen capture of each frame in your prototype and assemble them into one document, in flow order, with a short caption identifying each screen. Then set your Figma file's sharing to public (anyone with the link can view) and copy the link.

Important: Confirm the Figma link is truly public by opening it in a private/incognito browser window where you are not logged in. If it does not load, the share setting is wrong and your submission cannot be reviewed.

4. Parameters & Constraints

  • Coverage: the prototype must include screens for all use cases and actions documented in your previous assignments.
  • Connectivity: screens must be connected with Figma prototype links so the flows are clickable, not just a gallery of static frames.
  • Fidelity: low- to mid-fidelity is acceptable. Visual polish is not graded in this phase.
  • Screen-capture document: include one labeled capture per screen, in flow order.
  • Figma link: sharing set to public (anyone with the link can view).
  • Format: follow the file format your instructor or LMS specifies for submission.

5. Use of Generative AI

Generative AI is permitted and encouraged in this assignment. AI-accelerated prototyping is the subject of this module, so using AI coding assistants or AI design tools to scaffold and generate screens is part of the expected workflow.

Two requirements: (1) your team is responsible for assembling, connecting, and verifying the prototype — AI may generate pieces, but the coverage and flow decisions are yours; (2) briefly note where and how you used AI (a sentence or two). Anything AI generates should be reviewed by your team for fit against your documented use cases before it goes into the prototype.

6. Accessibility

Label all screens and controls in plain, direct language. In your screen-capture document, give each capture a short text caption describing the screen and what the user does on it, so the document is usable by readers using screen readers. If any team member needs an accommodation for producing or submitting materials, contact the instructor early — accommodations are available and will not affect your grade.

📥 What to Submit

Submit the following clearly labeled items as one team. Mark each item with its heading exactly as shown.

Deliverable 1 — Screen Capture Document

A document containing a screen capture of every screen in your prototype, in flow order, each with a short caption identifying the screen and the action it supports (Step 5).

Deliverable 2 — Public Figma Link

A link to your Figma prototype with sharing set to public (anyone with the link can view), verified in a logged-out browser window (Step 5).

Deliverable 3 — AI Use Note

One to two sentences describing how your team used generative AI in this phase.
